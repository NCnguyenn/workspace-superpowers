# Continuing an Existing Document

Use this contract when writing the next criterion, paragraph, section, or chapter of an existing report/thesis, or when making a substantive revision that must fit its surroundings. The document remains one argument in one project context. A new section must advance that argument rather than becoming an unrelated miniature report.

This contract extends the existing continuity profile. It does not create a parallel voice database or approval record, and it does not create a separate evidence register. A profile is source-grounded context for drafting and review; it does not prove that a section is approved, a claim is verified, or a project result was measured.

A completed-assignment read-back is different. Reading or remembering a completed assignment remains a narrow read-back operation. Do not extract a voice lock for enforcement, start drafting, or reopen intake merely because the artifact was read. Apply this profile only when the request is to continue, revise, draft from, or integrate the document.

## Inspect before continuing

For a folder-based report, retain the [project grounding record](project-grounding.md), including `context_file`, source provenance and revisions, coverage, conflicts, and heading-to-path mapping. For mathematics, preserve notation, assumptions, derivation IDs, and [check records](mathematics-checks.md). Continue from the latest adopted Word revision under [Equation fidelity](math-in-documents.md); do not regenerate from stale LaTeX over user edits.

Use `reading-artifacts` for files and `analyzing-artifacts` for interpretation. For pasted text, inspect it directly. Establish:

- the current document and version;
- the requested insertion point or edit seam;
- the applicable criterion or requirement;
- the output form: chat proposal or in-file edit;
- the source coverage and any uninspected representation.

Do not invent which criterion comes next when the source and conversation allow materially different choices.

Read the document structure, relevant introduction/objectives, immediately preceding passage, following passage if inserting, and referenced definitions, methods, results, tables, and figures. Follow dependencies beyond the neighboring paragraph when needed. For a long document, inspect targeted portions and record coverage; do not claim a whole-document read from a short excerpt. A changed or uncertain version requires a fresh read.

## Continuity profile

Capture applicable facts in the existing brief or conversation state with source locators and short representative excerpts. Reuse the existing profile, evidence register, work plan, and approval records. Do not create tracking files for an isolated continuation.

| Dimension | Record from the document and user instructions |
|---|---|
| Argument and placement | Document purpose, research question, chapter/criterion map, what preceding sections established, and what the new section must add. |
| Project context | Same system/scenario, actors, scope, technology, setting, dataset, method, time period, constraints, decisions, and limits. Distinguish implemented behavior, planned work, observation, interpretation, and illustrative material. |
| Evidence | Relevant claims, sources/locators, units, conditions, uncertainty, missing evidence, and unresolved contradictions. User-provided claims are not automatically verified. |
| Terminology | Preferred names, abbreviations already defined, notation, authorized translation choices, and terms that must not be interchanged. |
| Voice and register | Formality, narrative person, tense by function, certainty, paragraph development, and technical detail. Use actual surrounding prose as the reference. |
| Presentation | Heading hierarchy/numbering, paragraph/list/table usage, figure/table numbering and captions, citation convention, cross-references, and visible styles. |
| Boundaries | Requested section, preserve-list, requested change-list, output language, source coverage limits, unresolved conflicts, and authorized deviations. |

For every continuation or substantive revision, also record the inspected document/version, requested insertion point or seam, argument/criterion relationship, and output form. Keep locators and coverage limits beside each profile fact so a short excerpt cannot masquerade as a whole-document read. Keep this profile separate from `scope_status`, `outline_status`, `approval_record`, and `evidence_register`.

The profile does not prove that a section is approved, a claim is verified, or a project result was measured. It is a handoff aid for the writer and reviewers.

### Semantic locks and exceptions

Lock terminology only when the document or user establishes that words denote the same role or concept. Once established, preserve the adopted term and do not silently swap alternatives such as `teacher`, `lecturer`, and `professor`. Do not force one global word across distinct roles, quoted text, citations, references, examples, separate institutions, or source terminology. Report a material inconsistency when the document uses different terms for the same role. Co-occurrence alone is not a defect.

Lock the authorial narrative person only when the inspected document establishes one. Preserve objective voice, `the author`, `I`, or `we` according to context. Mixed person in the relevant authored prose is a review finding to surface. Exempt a verbatim quotation or a passage explicitly attributed to another person/source; an author's own sentence remains in scope even when it contains an in-text citation. Do not convert a group document into an individual account or vice versa without authorization.

Later criteria inherit the established project/scenario identity, actors, scope, technology, data, constraints, metrics, and decisions unless the user explicitly authorizes a change. Distinguish implemented behavior, planned work, observation, interpretation, and illustrative material.

Never invent a project name, module, role, technology, budget, timeline, metric, result, or test case to make a continuation fit. If sources contain multiple scenarios or a material contradiction, preserve the conflict with its locators and block silent reconciliation until the user or source resolves it. An explicit, scoped user correction can resolve a source contradiction for the authorized continuation; record that decision and retain the original locator. Do not turn an earlier tentative observation into a confirmed or production-wide result.

## Resolve precedence and limits

Apply precedence in this order:

1. explicit current instructions and adopted requirements for the affected scope;
2. explicit, still-applicable decisions and the existing document’s compatible conventions;
3. the [writing style guide](academic-writing-style.md) for gaps in clarity and presentation.

Do not reproduce factual errors, unsupported claims, inflated certainty, or unreadable prose merely to imitate the source. Flag material defects and correct them only within authorized scope; do not rewrite earlier chapters silently.

Follow the [language policy](language-policy.md). Source language alone is not an override of the English default. Honor an explicit applicable language instruction, including one to continue in the source language. If same-language integration and the selected output language conflict, clarify that specific conflict before insertion.

Preserve a coherent existing citation convention unless the user or adopted requirements specify a change. Use [citation style rules](citation-styles.md) when citations are required and no convention has been established. Do not introduce formal citations or external research solely to imitate academic prose.

## Compose the continuation

1. Apply the authorized operation and unresolved prerequisites from the [criteria-writing contract](criteria-writing-contract.md). “Continue section 3” reuses valid scope and outline decisions; it does not restart the report.
2. Identify the relationship to prior content: explanation, application, comparison, result interpretation, limitation, or next methodological step.
3. Write an explicit bridge at the actual seam from the immediately preceding argument to the requested contribution. Do not add a generic introduction or repeat definitions already established.
4. Develop only the requested contribution. Reuse established terminology, units, evidence limits, register, and presentation. Methods, results, and discussion may use different tense and structure when their function requires it.
5. Integrate evidence by claim or criterion, not by copying one source summary after another. Reconcile disagreements only with inspected evidence or an applicable user decision. Preserve prospective language for planned evaluations and tentative observations.
6. Check numbering, citations, figure/table references, captions, and adjacent transitions. Change neighboring text only within authorized scope; otherwise identify the small reconciliation needed.
7. Pass the profile, adjacent excerpts, evidence locators, target version, and preserve-list to the writing specialist and reviewers. Generic labels such as “academic tone” are not enough context.

## Review the seam and dependent content

Before delivering a substantive continuation in chat, and before reporting a DOCX edit/export complete, use the existing `reviewing-work` roles for scoped self-review. This is verification responsibility, not another user approval gate and not authority to rewrite protected earlier text.

- **Requirement review** checks the criterion, insertion point, boundaries, and adopted requirements.
- **Coherence review** reads the new text with relevant adjacent excerpts; it checks progression, contradictions, duplicated explanations, scenario drift, and dependent conclusions.
- **Prose review** compares actual passages for register, person, tense by function, role-aware terminology, paragraph/list usage, and presentation. Apply PEEL and lead-and-list checks from [academic-writing-style](academic-writing-style.md); 4–5 sentences is guidance, not a hard quota.
- **Evidence review** checks sources, conditions, certainty, repeated quantities, evidence status, citations, headings, numbering, cross-references, and captions. Reuse [visual assets and Word fidelity](visual-assets-and-word-fidelity.md) for native tables, embedded images, placement, template formatting, rendered layout, and capability limits.

Correct Critical and Important findings within authorization, or report the affected blocker with any permitted Important deferral and its justification. Reuse applicable analysis and detailed-outline decisions. After authorized drafting, deliver the complete section in chat, request review, and wait before moving to the next section.

Return concrete locations and fixes. Review only what was inspected and state missing context. Smooth standalone prose is insufficient when its transition or facts conflict with the document. Recheck affected seams after corrections and verify the final file after the last edit/export. Chat-only continuation receives content review without a claim that the source file was modified.

## Example

Earlier sections compare a baseline configuration and an indexed configuration on a staging catalogue and explicitly lack CPU data. The next section proposes further evaluation. Continue using those terms and limitations, and describe repeated trials and tail-latency measurement as future work. Do not rename the indexed configuration a cache, invent CPU savings, switch to a promotional bullet list, or claim that production users already benefited.
