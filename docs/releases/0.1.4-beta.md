# Workspace Superpowers 0.1.4-beta

This beta addresses assignment intake and an approval interaction in which a user
is asked to approve an analysis they cannot see. It also removes conflicting
instructions that could continue an old workflow instead of handling the current
request. This is an instruction-pack update, not a replacement question UI.

## Changes

- Read newly supplied assignment guides and map deliverables, source locators,
  criterion obligations, failure constraints and contradictions before setup
  questions when no section is named. Ask only what the source has not settled.
- Choose skills from the current request and retained context. Load the relevant
  skill before acting, including a possible match under the one-percent rule.
  Load additional dependencies when their work begins; do not preload the catalog
  or force every request through the full writing lifecycle.
- Reuse an existing intake map on continuation. Read supplied sources before
  scoping, and keep pending approvals local to the work that depends on them.
- Ask one material clarification at a time. Missing evidence may use a focused
  native question card when permitted. Using that card does not request later
  approval cards.
- Show the complete analysis or detailed outline before its natural chat review
  question. Explicitly requested approval cards require the content to be visible
  first; use chat when the host cannot preserve that display order.
- If the user reports missing content, present the full proposal and keep its
  approval pending. Do not open another approval card or advance to an outline
  or draft. If the proposal has not been prepared, load its responsible skill and
  prepare it; if required evidence is missing, ask only about that gap.
- Keep internal labels such as “Stop 2” out of user-facing questions and options.
- Preserve separate analysis and detailed-outline approvals, source-grounded
  evidence, English deliverable defaults, small-edit routes and file verification.

The package still contains 23 skills and requests only `agent.prompt.inject`.
No new tools, permissions or question UI are introduced.

## Installation

Install `local.workspace-superpowers-0.1.4-beta.piplug` through the PI-Desktop
Plugins page, reload the plugin and start a fresh chat. Check the 23-skill catalog.
The SHA-256 sidecar and `build-record.json` identify the inspected package.
Packaging does not update an already installed plugin or global instructions.
See [installation and rollback](../../adapters/pi/install.md).
