# Workspace Superpowers 0.1.6-beta

The native PI-Desktop adapter now registers an agent extension instead of returning
a system prompt from a plugin-process notification handler. Inspection of
PI-Desktop 0.15.9 established that the latter ignores the callback return value.
This explains why the earlier mocked hook tests did not establish real injection.

The manifest now requires `agent.extension` in addition to `agent.prompt.inject`.
It contributes `adapters/pi/agent-extension.js`; the package builder translates
the CommonJS source extension to the `.js` entry accepted by the native loader.
The extension reads bundled instructions, modifies only its returned system
prompt, registers no tools, writes no files and makes no network requests.
The declared/tested desktop minimum is 0.15.9.

The bootstrap is thin. Analysis/outline approval, evidence requirements,
source-first intake, language policy, citation completion and document continuity
remain in the existing router, specialists and references. The 24 skills and
their IDs are unchanged. Each Workspace turn still loads the router, then the
specialists selected for that operation. There is no unverified router-cache mode.

A separate Pi CLI extension registers native discovery and `before_agent_start`.
Its absolute paths are independent of the working project. Session start and
compaction invalidate its template cache; a missing bootstrap is reported rather
than silently implying successful activation. Pi CLI uses native `read`, while
PI-Desktop uses the namespaced native `Skill` tool.

## Verification boundaries

Architecture checks establish rule ownership and package references. Adapter
tests execute registration, repeated turns, restored prompts and block refresh.
Package checks reopen the generated native entry, archive and every file byte.
The optional pinned-host probe checks the actual PI-Desktop Jiti loader, extension
runner and prompt application method without network, credentials or model calls.
None of these checks establish a model's multi-turn skill compliance or DOCX/PDF
rendering quality. Those remain PENDING/UNVERIFIED in the existing native trials.

Build into a fresh directory with `python scripts/package-pi.py --out
dist/pi-orchestration-0.1.6-beta`. Install through PI-Desktop's native plugin flow
and review the additional `agent.extension` permission. Preserve the plugin's
existing enabled state and project scope. A build alone does not update the app.

long workflow instructions. Replace only the explicitly adopted plugin block
when migrating such a project, keeping its custom instructions.

restore the prior permission set through the host UI. The earlier version has
the known notification-hook limitation; project bootstrap fallback remains an
option when native extension permission is unavailable.
